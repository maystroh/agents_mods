# Reflect

When the user asks to remember a correction or make a behavior change persist, state the specific rule and choose the narrowest suitable home: project `AGENTS.md` for project behavior, a relevant existing skill for a specialized workflow, or user-level Codex instructions for genuinely global preferences. Check existing guidance first and merge with it instead of duplicating or contradicting it.

Apply the rule when the destination is clear and writable. For a global rule, use the user's requested location or established local convention. Show the exact file changed and summarize the rule. A simple correction during a task should first be fixed in the current work; do not silently turn every correction into a lasting rule.
